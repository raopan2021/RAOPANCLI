# 2026-08-25

## RAOPANCLI 脚手架项目全面完善

1. **依赖升级**：chalk 6.0.0、commander 15.0.0、figlet 1.11.4、fs-extra 11.4.0、inquirer 14.1.0、ora 9.4.1、vitepress 1.6.4、@antfu/eslint-config 9.3.0、eslint 10.9.1、eslint-plugin-format 2.0.1、jiti 2.7.0。**移除 shelljs**（改用 node:child_process），新增 archiver 8.0.0（跨平台 zip）、boxen 8、gradient-string 3、dayjs（build 美化）。engines node >=20.17.0，files 字段限定 npm 发布内容（bin/lib/README）。

2. **antfu 格式化**：eslint.config.ts（typescript:true、stylistic 2空格单引号、formatters css/html；忽略 lib/**、docs 教程 md、.github/**、.codebuddy 等；no-console 与 node/prefer-global/process 关闭）。.editorconfig 改 2 空格 LF UTF-8。.vscode/settings.json 保存时 eslint fix。`pnpm lint` / `pnpm lint:check`。ESLint 10 加载 TS 配置必须装 jiti。

3. **跨平台兼容**（原来仅 Windows 可用）：
   - 所有 `import.meta.url.replace('file:///','')` → `fileURLToPath`（bin/index.js、create.js、deploy.js）
   - run.js 压缩：powershell Compress-Archive → archiver `new ZipArchive()`（archiver 8 是 ESM named export）
   - deploy.js：nginx.exe/nginx 按平台区分；Windows 枚举 C~Z 盘、非 Windows 从 `/` 搜索；重启 Windows 用 bat+cmd.exe、Linux/Mac 用 `nginx -s reload`；修复 getDistPath 的 fs.access 永远 truthy 的 bug、getNginxHtml 的 `stats.isDirectory` 漏括号 bug
   - delete_node_modules.js 递归手动删除 → `fs.rmSync(recursive)`

4. **CLI 美化**：scripts/build.mjs（参考 partner-collab-platform-web/build/info.ts）用 boxen+gradient-string+dayjs 输出欢迎横幅、构建耗时（模块转换/总用时）、产物体积统计；直接调用本地 `node_modules/vitepress/bin/vitepress.js` 避免依赖 PATH。`pnpm build` 即走此流程。

5. **命令简化**：package.json bin 新增 `"rp"` 别名（保留 raopancli）。删除 printHelp.js（改用 commander 原生 `.version()`/`.helpOption()`）。`-dn` 短参在 commander 15 会抛错（多字符短参非法），改为 `-D`。**inquirer 14 移除了 `list` 类型，全部改为 `select`**（run/create/deploy/setMirror 共 6 处）。各 prompt 增加 .catch 取消容错。

## 部署功能完善（deploy.js 重构）
- **命令变更**：部署 `-d` → **`-n`**，新增恢复备份 **`-N`**（index.js 同步更新）
- 重写 bin/functions/deploy.js，新增：
  - 交互式选 nginx 服务器：已知记录 / 手动输入（校验含 nginx 可执行文件）/ 自动搜索
  - 部署文件夹：选择已有 / **新建（ensureDirSync 支持多层 a/b/c）** / **重命名（fs.moveSync）** / 返回上一步
  - **step 状态机**（1=选服务器,2=选文件夹,3=确认），确认取消退回选文件夹、文件夹返回退回到服务器
  - **自动备份**：部署前将目标目录整体拷贝到 `bin/memory/deploy-backups/<project>_<dirname>_<timestamp>`
  - **记录部署配置**到 nginxServer.json 的 `projects[projectName]`，下次运行 `-n` 弹"一键确认"
  - `-N` 恢复：从备份列表选择，覆盖当前部署目录
  - 备份目录/内存文件路径可注入（`_setPaths`），导出 `readMemory/writeMemory/makeBackup/listBackups/getNginxHtml/restartNginx` 供测试
- 新增 test/deploy-test.mjs（8 项断言：内存读写、自动备份、恢复、多层目录、getNginxHtml），`pnpm test` 已接入（z.js + deploy-test.mjs），测试自动清理 test-tmp
- 注意：inquirer 14 无 `list` 类型，全部用 `select`；交互流程依赖 TTY，管道/CI 下无法驱动 select 选择（已用 confirm 支持非交互默认）
- nginxServer.json 默认结构已含 `projects` 字段（旧版只有 nginxPath/nginxList，readMemory 容错兼容）
